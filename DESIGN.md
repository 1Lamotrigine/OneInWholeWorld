# DESIGN.md — визуальная система Fantasy Life

> Статус: утверждённое направление для MVP. Основной референс — **второй концепт: тёмный пиксельный симулятор жизни**. Это не RPG-инвентарь и не лендинг: интерфейс наблюдения за судьбой персонажа, вдохновлённый информационной компоновкой 1in8b, но с собственной визуальной идентичностью.

## 1. Принципы

1. **Сначала жизнь, потом декор.** На первом экране видны возраст, управление временем, текущая сцена, важное решение и летопись.
2. **Пиксель-арт — в изображениях, современный UI — в управлении.** Не использовать пиксельные шрифты для длинных текстов.
3. **Информационная плотность без шума.** Компактные карточки, тонкие границы, понятная иерархия, без тяжёлых золотых орнаментов.
4. **Одна игра на всех экранах.** Перестраивать порядок блоков, не уменьшать десктопную версию целиком.
5. **Решения понятны.** Последствия можно обозначать подсказками, но не раскрывать скрытые броски.
6. **Доступность и производительность.** Контраст, клавиатура, reduced motion, изображения с резервными состояниями.

## 2. Визуальный язык

**Характер:** сдержанное тёмное фэнтези, лёгкая ностальгия по 16-bit играм, ощущение живой летописи. Без стекломорфизма, неоновых градиентов, массивных теней и декоративных рамок вокруг каждого блока.

Цвет **не должен быть единственным** носителем смысла: сопровождать его текстом/иконкой. Проверить контраст текста не менее 4.5:1 для обычного текста и 3:1 для крупного; при необходимости скорректировать оттенки.

### Типографика

- Интерфейс и длинные события: **Inter** или `system-ui`, 14–16 px, line-height 1.5–1.65.
- Заголовки и имя персонажа: **Literata** или **Merriweather**, умеренно, не на каждой кнопке.
- Числа, возраст, значения шкал: tabular numerals.
- Минимальный основной текст на мобильных: 14 px; описания событий лучше 15–16 px.
- Масштаб: H1 28–36 px desktop / 24–28 px mobile; H2 18–22 px; заголовки карточек 16–18 px.
- Не использовать капслок для длинных подписей и не вставлять текст в растровые изображения.

### Формы и ритм

- Базовый шаг отступов: 4 px; типичные расстояния 8 / 12 / 16 / 24 px.
- Радиус карточек: 8 px; кнопок: 6–8 px; чипов: 999 px.
- Граница: 1 px `--border`; тени минимальные.
- Пиксель-арт показывать с `image-rendering: pixelated` **только** если исходный ассет рассчитан на целочисленное масштабирование; избегать размытия и нецелых коэффициентов.
- Иконки: единый набор (Lucide), 16–20 px, без смешения эмодзи с основными пиктограммами.

## 3. Информационная архитектура

### Основные экраны

1. **Старт**: короткий тезис «Кем ты родишься в Эларионе?», кнопка «Начать жизнь», возможность продолжить сохранение, компактная иллюстрация мира.
2. **Рождение**: анимированное раскрытие расы, региона, семьи, статуса, стартовых особенностей; кнопка «Прожить жизнь»; нельзя вручную выбирать расу в основном режиме.
3. **Жизнь**: главный симулятор, центральный экран продукта.
4. **Завершение жизни**: возраст, причина смерти, главные вехи, статистика, «Поделиться судьбой», «Новая жизнь».
5. **Сохранения и настройки**: список локальных прохождений, экспорт/импорт, управление звуком и анимацией.

Не создавать отдельные страницы для каждого второстепенного элемента на MVP. Семью, мир, профессии и подробные характеристики можно раскрывать в панелях/диалогах.

## 4. Главный экран: десктоп

### Верхняя панель

- Слева: лаконичный логотип/название «Жизнь в Эларионе».
- По центру или справа: «Жизнь», «Мир», «Летопись», «Сохранения» (в MVP можно часть оставить вкладками внутри игры).
- Настройки — отдельная иконка с доступным названием.
- Следующая строка: **возраст, текущий год, прогресс игрового года**, затем Play/Pause, `1× 2× 4× 8×`, «До решения», «Авторежим» (если реализован).
- Управление не должно занимать больше 1–2 компактных строк на широком экране.

### Сетка

Для контейнера до 1440 px, максимальная ширина контента 1480 px, боковые поля 20–32 px:

```text
┌────────────────────────────────────────────────────────────────────┐
│ Логотип / навигация / настройки                                   │
├────────────────────────────────────────────────────────────────────┤
│ Возраст 18  ·  Год 1248  ━━━━━━━━━  ▶ 1× 2× 4× 8×  Авторежим     │
├─────────────────┬────────────────────────────┬─────────────────────┤
│ ПЕРСОНАЖ        │ ПИКСЕЛЬНАЯ СЦЕНА           │ СЕМЬЯ               │
│ портрет         │ текущая локация            ├─────────────────────┤
│ раса/регион     ├────────────────────────────┤ ХОД ЖИЗНИ          │
│ происхождение   │ ФОКУС / ВАЖНОЕ РЕШЕНИЕ    ├─────────────────────┤
│ характеристики  ├────────────────────────────┤ ЧЕРТЫ / МИР        │
│                 │ ЛЕТОПИСЬ                  │                     │
└─────────────────┴────────────────────────────┴─────────────────────┘
```

- Сетка: `minmax(260px, 0.95fr) minmax(0, 1.8fr) minmax(250px, 0.9fr)`; gap 16–20 px.
- **Центральная колонка главная**: не менее ~45% полезной ширины на больших экранах.
- Слева портрет и данные; **портрет умеренный** (например 112–160 px), не огромная иллюстрация на половину экрана.
- В центре сцена (примерно 16:7 или 16:8), затем решение/годовой фокус, затем **просторная летопись**.
- Справа семья, жизненный прогресс и черты/контекст мира.
- Длинные события переносятся по строкам, без обрезания важных фрагментов.

## 5. Планшеты и смартфоны

### Брейкпоинты

- `>= 1200px`: три колонки.
- `768–1199px`: две колонки; основная область + вспомогательная панель; семью и дополнительные блоки переносить ниже.
- `< 768px`: одна колонка, никакого горизонтального скролла страницы.
- `< 380px`: сокращать вторичные подписи, не уменьшать touch-target и основной текст.

### Мобильный порядок

1. Компактная шапка: название, меню/настройки.
2. **Sticky-панель**: возраст, год, пауза/продолжить, выбор скорости (с учётом safe-area).
3. Пиксельная сцена, широкая и невысокая.
4. Важное решение или годовой фокус — выше длинных данных персонажа.
5. Летопись жизни (последние события, кнопка «Показать всё»).
6. Свернутая карточка персонажа: небольшой портрет, имя, раса, статус, ключевые показатели.
7. Семья, черты, контекст мира в раскрывающихся секциях.

На мобильном **не** делать постоянную трёхколоночную панель или гигантский портрет. Навигация — компактное меню/нижние вкладки только при реальной необходимости. Панель управления не должна перекрывать выбор события или системную клавиатуру.

### Touch и responsive

- Интерактивные области не менее **44×44 CSS px**; между соседними действиями достаточный зазор.
- `viewport` и `env(safe-area-inset-bottom)` для нижних закреплённых элементов.
- Не полагаться на hover; все подсказки доступны по нажатию/фокусу.
- Поддержать 200% масштаб текста без потери функций.
- Изображения `width: 100%`, `height: auto`, заданный `aspect-ratio`; резервная картинка при отсутствии ассета.

## 6. Компоненты и состояния

### `GameHeader` / `TimeControls`

- Отображают возраст, год, прогресс, статус воспроизведения.
- Состояния: играет, пауза, ждёт решения, завершено, восстановление сохранения.
- Скорости: 1×, 2×, 4×, 8×; активная выделена не только цветом.
- Кнопка «До следующего решения» работает только если механика реализована; иначе не показывать.
- Клавиатурное управление (например пробел для Play/Pause) только когда фокус не в поле ввода и не в диалоге.

### `CharacterSummary`

- Портрет 112–160 px на десктопе, 56–80 px на мобильном.
- Имя, возраст, раса, регион, происхождение, статус, профессия.
- Показатели: здоровье, счастье, знания, отношения; дополнительные — по необходимости.
- Шкалы с текстовым значением и доступным `aria-label`/`progressbar`.

### `ScenePanel`

- Пиксельная локация зависит от региона, сезона, достатка, важного жизненного этапа.
- На MVP достаточно 5–8 фоновых сцен и небольших персонажей/спрайтов; не генерировать уникальную картинку на каждый год.
- Короткая подпись под сценой объясняет, где персонаж живёт и что происходит.
- Ассеты хранить локально в `public/art/`, использовать Next `Image` при уместности.

### `DecisionCard` / `YearFocus`

- Важное событие имеет заголовок, 1–3 абзаца контекста и 2–4 осмысленных варианта.
- Кнопки содержат действие, а не абстрактное «Да/Нет».
- На мобильном варианты — вертикально, на всю ширину.
- При ожидании обязательного выбора симуляция ставится на паузу; после выбора отображается результат.
- Годовой фокус — компактные чипы/радио-выбор; отдельный блок от критических решений.

### `LifeChronicle`

- Самая важная текстовая область после сцены/решения.
- Записи: возраст/год, короткое событие, приоритет/категория, при необходимости разворачиваемые подробности.
- Сортировка: новые сверху по умолчанию; переключатель хронологии при необходимости.
- Цветовые акценты: достижения — золотой, потери — приглушённый красный, нейтральные — обычный текст.
- Для больших летописей использовать виртуализацию или порционную загрузку из локального хранилища; не рендерить тысячи DOM-узлов сразу.
- При автосимуляции не перехватывать прокрутку, если пользователь читает старые события.

### `FamilyPanel`, `LifeProgress`, `TraitsPanel`

- Семья: роль, имя, возраст/статус, отношения; на MVP без обязательных портретов каждого родственника.
- Ход жизни: сегменты прожитых лет/этапов, **не показывать точный возраст смерти как предсказанный факт**; если есть оценка, явно подписать «ожидаемая продолжительность».
- Черты: короткие подписи и объяснение эффекта по запросу.

### `DeathSummary` / `ShareCard`

- Итоги: происхождение, возраст, причина смерти, ключевые события, итоговый статус.
- Действия: «Новая жизнь», «Сохранить изображение», «Поделиться».
- Экспорт изображения полностью клиентский; не обещать публичную ссылку без механизма сериализации/seed.

## 7. Пиксель-арт: правила производства

- Стиль: **16-bit inspired**, чистые силуэты, приглушённые природные цвета, умеренная детализация.
- Ассеты: портреты рас, деревня/город/лес/горы/подземелье, сезонные вариации, несколько семейных и возрастных состояний.
- Не смешивать в одной сцене реалистичные лица, 3D-рендеры и пиксельные спрайты.
- Базовые сцены: 640×280 или 640×320 px (пример), с масштабированием по пропорциям; персонажи на единой пиксельной сетке.
- Предусмотреть fallback по `race + region + lifeStage`, а не требовать картинку для каждой комбинации.
- Анимации по желанию: огонь, облака, свет окон, вода; отключаются при `prefers-reduced-motion`.
- Права на ассеты должны позволять использование в проекте; вести `public/art/ATTRIBUTION.md` для сторонних ресурсов.

## 8. Микровзаимодействия

- Hover/press: 120–180 ms; мягкая смена фона/границы.
- Появление события: 150–250 ms без тяжёлых сдвигов.
- Прогресс года обновляется плавно, но не вызывает постоянный re-render всего интерфейса.
- При рождении — короткое раскрытие результата; обязательная кнопка пропуска анимации.
- При смерти — спокойное, уважительное завершение, без навязчивых вспышек и тряски.
- Уважать `prefers-reduced-motion` и настройку отключения анимаций.

## 9. Реализация в Next.js / Tailwind

- Все интерактивные компоненты — клиентские (`'use client'`), без зависимости от SSR для PGlite.
- Дизайн-токены задавать CSS custom properties в `globals.css`, подключать к Tailwind theme.
- Компоненты должны получать состояние через props/selectors, не обращаться напрямую к PGlite.
- Zustand — UI/активная симуляция; PGlite — сохранения, история и восстановление.
- Использовать CSS Grid для десктопа, простой поток и Flex/Grid для мобильного.
- Для анимаций предпочитать CSS; тяжёлые библиотеки добавлять только по необходимости.
- Изображения и шрифты загружать с контролем веса; предусмотреть skeleton для восстановления сохранения.

## 10. Пустые и проблемные состояния

- **Нет сохранений:** понятное приглашение начать первую жизнь.
- **Нет сцены:** стилизованная заглушка с названием локации; симуляция продолжает работать.
- **Нет событий:** спокойный текст «Пока ничего примечательного не произошло».
- **Загрузка PGlite:** индикатор и объяснение «Восстанавливаем летопись…».
- **Ошибка сохранения / заполнено хранилище:** не скрывать ошибку, предложить экспорт.
- **Недоступна Web Share API:** кнопка скачивания изображения или копирования текста.
- **Персонаж умер:** блокировать продолжение времени, оставить доступ к летописи и итогам.

## 11. Проверка адаптивности и качества

Проверять вручную и автоматизированно минимум на ширинах **320, 375, 430, 768, 1024, 1280, 1440, 1920 px**, а также при увеличенном масштабе браузера.

**Критерии готовности:**

- [ ] Ни на одном размере нет горизонтального скролла страницы.
- [ ] На мобильном важное решение доступно без поиска по второстепенным панелям.
- [ ] Управление временем доступно и не перекрывает контент.
- [ ] Клавиатурой доступны все кнопки, вкладки и раскрытия; фокус видим.
- [ ] Текст читается без увеличения; контраст проверен.
- [ ] Пиксельные сцены не растянуты и не искажают пропорции.
- [ ] UI не скачет при обновлении года/события.
- [ ] 100+ записей летописи не вызывают заметных лагов.
- [ ] Работают загрузка, пустые состояния, смерть, восстановление сохранения.
- [ ] Reduced motion отключает необязательные эффекты.

## 12. Приоритет реализации

**Этап 1 — каркас:** токены, шапка, responsive grid, карточки и временные данные.

**Этап 2 — игровой экран:** управление временем, персонаж, сцена, выбор, летопись и правая колонка.

**Этап 3 — мобильная версия:** переупорядочивание блоков, sticky controls, доступные действия.

**Этап 4 — контент:** единый набор пиксельных сцен/портретов и fallback-ассеты.

**Этап 5 — полировка:** переходы, состояния, доступность, производительность, скриншотные проверки.

## 13. Чего НЕ делать

- Не копировать 1in8b пиксель-в-пиксель, не повторять чужие иллюстрации и брендинг.
- Не превращать главный экран в RPG с инвентарём, оружием, квестовой картой и огромными портретами.
- Не использовать золотую обводку на каждом элементе; золото — редкий смысловой акцент.
- Не делать мобильный интерфейс уменьшенной копией десктопа.
- Не прятать летопись за несколькими переходами.
- Не добавлять бэкенд, обязательный аккаунт или облачную синхронизацию для реализации дизайна.

---

**Итог:** современный, плотный, читаемый симулятор жизни с пиксельной сценой как эмоциональным центром. Главный пользовательский цикл: **родиться → наблюдать → решать → читать летопись → делиться судьбой → начать снова**.
